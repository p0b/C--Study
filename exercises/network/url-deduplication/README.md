# 练习 4：URL 爬虫去重系统 (双层防御)

## 场景描述
我们的爬虫需要处理海量 URL（假设 10 万条），必须避免重复爬取。直接用 `std::set` 太费内存，只用布隆过滤器又有误判。
我们需要构建一个**"保安大叔 (Bloom Filter) + 前台小姐姐 (Hash Table)"**的双层防御系统。

## 核心架构
1.  **第一道防线：布隆过滤器**
    - 快速判断 URL 是否**可能**存在。
    - 如果布隆过滤器说"不在"，那肯定不在 -> **直接爬取**。
    - 如果布隆过滤器说"在"，那可能是真的在，也可能是误判 -> **进入第二道防线**。

2.  **第二道防线：哈希表 (或数据库)**
    - 在这里我们用 `std::unordered_set` 模拟昂贵的数据库查询。
    - 只有被布隆过滤器标记为"可疑"的 URL，才需要查这里。
    - 这里的查询结果是 100% 准确的。

## 技术要求
- 复用之前写的 `BloomFilter` 类（代码复用！）。
- 结合 `std::unordered_set` 实现去重逻辑。
- 统计：
    - 布隆过滤器拦截了多少？
    - 哈希表确认了多少？
    - 实际节省了多少次昂贵的哈希表查询？

## 验证方法
1.  生成 50,000 个随机 URL 作为"历史记录"。
2.  生成 50,000 个新 URL（其中混入 10,000 个重复的）。
3.  跑一遍去重流程，看能不能把那 10,000 个重复的揪出来，同时不误杀新的。
