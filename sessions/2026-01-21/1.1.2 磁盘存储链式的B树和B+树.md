## 1 什么叫做M阶B树
### 问题
什么叫做 M 阶 B 树

### 回答
+ **M 阶的本质含义是最大分支数** 一个节点**最多有 M 个子树指针**
+ 由结构恒等式得到 **关键字数 = 子树数 - 1** 所以一个节点最多 **M-1 个关键字**
+ B 树的关键目标是“宽而矮”，减少外存访问次数

### 图示：节点结构关系
```plain
一个节点含 k 个关键字时，必有 k+1 个子树

T0 | K0 | T1 | K1 | T2 | ... | K(k-1) | Tk
```

## 2 什么是关键字 什么是子树 为什么 ⌈M/2⌉ 个子树推出 ⌈M/2⌉-1 个关键字
### 问题
+ 什么是关键字
+ 什么是子树
+ 为什么能由非根节点至少有 ⌈M/2⌉ 个子树推出至少有 ⌈M/2⌉ - 1 个关键字

### 回答
+ **关键字**是用于比较大小、决定向哪个子树继续查找的分割点
+ **子树**是节点中指向下一层的指针所代表的一整棵树，每棵子树负责一个连续值域区间
+ 推导来自结构必然性 **k 个关键字把值域切成 k+1 个区间** 区间在 B 树中实体化为子树指针 所以 **子树数 = 关键字数 + 1** 得到 **关键字数 = 子树数 - 1** 因此子树至少 ⌈M/2⌉，关键字至少 ⌈M/2⌉-1

### 图示：分割点与区间
```plain
关键字:     K0      K1      K2
区间:   (-∞,K0) (K0,K1) (K1,K2) (K2,∞)
子树:      T0      T1      T2      T3
```

## 3 SUB_M 代表什么 为什么 childrens 是二级指针
### 问题
+ 这里的 SUB_M 代表什么
+ 为什么 `struct btree_node **childrens` 有两个 *

### 回答
+ `SUB_M` 在很多实现里可能是两种含义之一 1 作为“阶 M” 2 更常见是作为最小度数 t
+ 你图中注释“keys 5”“children 6”强烈暗示用的是最小度数 t=3 的 CLRS 风格 因为
    - 最大关键字数 `2t-1 = 5`
    - 最大孩子数 `2t = 6`
+ `childrens` 之所以是 `**` 因为它要存“孩子指针数组”的首地址 数组元素类型是 `struct node*` 数组首地址类型自然是 `struct node**`

### 图示：指针数组
```plain
childrens  ---->  [ p0 | p1 | p2 | p3 | p4 | p5 ]
                   |    |    |    |    |    |
                   v    v    v    v    v    v
                 子节点 子节点 子节点 子节点 子节点 子节点
```

## 4 B树添加 插入流程 举例说明
### 问题
能给我讲讲 B 树的添加吗 请举例说明

### 回答
+ 插入核心策略是工程常用的**自顶向下预分裂**
    - 下探时遇到满节点先分裂
    - 保证最终落到叶子时叶子必不满
+ 分裂规则
    - 中位关键字上移到父
    - 左右各保留 t-1 个关键字
    - 内部节点还要搬移对应子指针

### 图示：分裂的结构动作
以满节点 y 为例

```plain
y: [ K0 K1 ... K(t-2)  K(t-1)  Kt ... K(2t-2) ]

分裂后:
父节点插入 K(t-1)

左节点:  [ K0 ... K(t-2) ]
右节点:  [ Kt ... K(2t-2) ]
```

## 5 B树删除 总体思路与三大原语
### 问题
给我讲讲删除呢

### 回答
删除的本质目标是避免节点下溢 非根节点至少 `t-1` 个关键字

删除中只有三种修复原语

+ **借位**：向富兄弟借，父关键字下放，兄弟关键字上提，内部节点还要移动子指针
+ **合并**：两兄弟都瘦，父分隔关键字下放，把两兄弟合成一个满节点
+ **根缩高**：根被合并到空则高度减一

### 图示：三原语概览
```plain
借位: 兄弟(富) -> 父 <-> 子(瘦)
合并: 子(瘦) + 父分隔key + 子(瘦) => 一个节点
缩高: 根无key且只有一个孩子 => 孩子变新根
```

## 6 怎么删除内部节点
### 问题
怎么删除内节点呢

### 回答
内部关键字不能直接删，三选一

1 左孩子至少 t 个关键字

用前驱替换，再删前驱

2 右孩子至少 t 个关键字

用后继替换，再删后继

3 两边都只有 t-1

合并左右孩子与该关键字，再在合并节点中删

### 图示：内部删除三选一
```plain
命中内部key k

情况1: left.n >= t
k <- pred(left) ; delete pred in left subtree

情况2: right.n >= t
k <- succ(right) ; delete succ in right subtree

情况3: left.n = right.n = t-1
merge(left, k, right) ; delete k in merged node
```

## 7 复杂例子讲解借位
### 问题
你能举一个复杂的例子来讲解一下借位吗

### 回答
借位本质是“旋转”

+ 父的分隔关键字下放到瘦孩子
+ 兄弟提供一个关键字上提替换父分隔关键字
+ 内部节点借位必须移动一棵子树指针来保持区间正确

### 图示：从左兄弟借位的旋转
```plain
parent: [... | A | ...]
                 /         \
       left(L)               child(y)

借位:
1 parent.key(A) 下放到 y
2 L 的最大key 上提到 parent.key(A)
3 L 的最右子树指针移交给 y 的最左子树槽位
```

## 9 为什么要移动 MN
### 问题
为什么要移动 MN

### 回答
移动 MN 有两个必然原因 1 区间归属改变 根分隔从 O 变为 L 后，MN 中的值都大于 L，必须归右子树，否则搜索路径错误 2 结构恒等式必须维持 内部节点始终满足 **孩子数 = 关键字数 + 1** 左节点关键字减少 1 就必须减少 1 个孩子 右节点关键字增加 1 就必须增加 1 个孩子 这个孩子就是 MN

### 图示：错误后果
```plain
借位后根: [L]

如果 MN 仍在左子树:
查找 M:
根判断 M > L => 走右
实际 M 在左 => 必然找不到或路径错
```

## 11 最小度数 t 是什么 代码怎么解读 assert 是什么
### 问题
+ t 表示最小度数 什么是最小度数 在 B 树中怎么体现
+ 构造函数这两段怎么解读
+ assert 是什么 有什么作用

### 回答
#### 最小度数 t 的定义与体现
+ t 控制节点的最少装载量与最大容量
    - 最大关键字 `2t-1`
    - 最大孩子 `2t`
    - 非根最少关键字 `t-1`
    - 非根最少孩子 `t`
+ t 越大树越矮，但单节点更大

#### 代码 1 解读
```plain
BTreeNode(int t, bool isLeaf)
  : leaf(isLeaf), n(0),
    keys(2*t - 1, 0),
    c(2*t, nullptr) {}
```

含义

+ leaf 用 isLeaf 初始化
+ n 初始化为 0 表示当前有效 key 数为 0
+ keys 预分配最大 `2t-1` 容量，初值 0
+ c 预分配最大 `2t` 个孩子指针槽位，初值为空指针 重点是 keys 和 c 的长度是容量上限，实际使用由 n 控制

#### 代码 2 解读
```plain
explicit BTree(int t_) : t(t_), root(new BTreeNode(t_, true)) {}
```

含义

+ explicit 防止隐式转换误构造
+ 固定整棵树的最小度数 t
+ 创建一个初始根节点，空树时根也是叶子

#### assert 的作用
+ 运行时断言 条件不满足立即终止，帮助你在不变量被破坏的第一现场定位 bug
+ 典型用在数据结构里验证前置条件，例如分裂函数要求被分裂节点必须满

# 14 B+树复盘补全
虽然本次对话主要围绕 B 树，但为了你“B树与B+树”一起复盘，这里补上 B+树的关键对比点，便于形成完整框架。

## 14.1 B+树是什么
B+树是 B 树的工程变体，核心改动

+ **所有数据记录只存放在叶子节点**
+ 内部节点只存“索引关键字”，不存真实数据记录
+ 叶子节点通常按链表顺序连接，支持高效范围扫描

## 14.2 B树与B+树核心差异表
+ 数据存放位置
    - B 树：内部节点和叶子都可能存数据
    - B+树：数据只在叶子
+ 查找路径一致性
    - B 树：命中内部节点可提前结束
    - B+树：必须走到叶子，路径长度更稳定
+ 范围查询与排序扫描
    - B 树：范围查询需要中序遍历跨层跳转
    - B+树：叶子链表顺序扫描更快
+ 扇出与高度
    - B+树内部节点更“纯索引”，同页能容纳更多 key，通常扇出更大，高度更低

## 14.3 B+树叶子链表图示
```plain
内部层:      [  M  ]
            /      \
叶子层: [ ... ] -> [ ... ] -> [ ... ] -> ...
          顺序指针连接，范围查询直接扫
```

## 14.4 为什么数据库更偏爱 B+树
+ 更稳定的磁盘访问路径
+ 范围查询与排序更高效
+ 内部节点只存索引，扇出更大，树更矮
