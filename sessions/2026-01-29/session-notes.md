## 核心知识点

### 1. 适配器模式 (Adapter)
- **核心思想**：将一个类的接口转换成客户希望的另一个接口。
- **生活梗**：USB拓展坞（Type-C 转 USB-A）。
- **C++ 关键点**：
    - **组合优于继承**：使用对象适配器（持有 `Adaptee*`），而不是类适配器（多重继承）。
    - **STL 应用**：`std::stack` 和 `std::queue` 是容器适配器，底层默认用 `std::deque`。
- **代码模型**：
  ```cpp
  class Adapter : public Target {
      Adaptee* adaptee_; // 组合
  public:
      void Request() override {
          adaptee_->SpecificRequest(); // 转发
      }
  };
  ```

### 2. 外观模式 (Facade)
- **核心思想**：为子系统中的一组接口提供一个一致的界面。
- **生活梗**：饭店服务员（一键点菜，不用去后厨指挥洗菜切菜）。
- **业务场景**：一键启动智能家居（灯+空调+电视）、一键初始化游戏引擎（图形+音频+网络）。
- **代码模型**：
  ```cpp
  class Facade {
      SubsystemA* a_;
      SubsystemB* b_;
  public:
      void Operation() {
          a_->Action();
          b_->Action();
      }
  };
  ```

## 遇到的问题与澄清
- **组合 vs 继承**：在适配器模式中，明确了使用组合（Composition）比继承（Inheritance）更灵活，且能保护被适配者的接口不被污染。
- **外观模式的持有方式**：外观类通常通过组合持有子系统对象的指针，负责协调调用顺序。
